# Tinker mini-swe timeout diagnosis

## Conclusion

The 15 first-turn timeouts in the coding-pool pilot were caused by an oversized
sampling seed generated by this repository's mini-swe adapter. They were not
caused by the selected models, real SWE-bench prompt content, prompt length,
tool declarations, renderers, credentials, or the Docker harness.

The failing code used:

```text
sampling seed = experiment seed × 1,000 + call index
```

With an experiment seed near `20,260,726`, the first Tinker request therefore
received a seed near `20,260,726,000`. Tinker SDK 0.23.1 accepted the value, but
the backend request remained unresolved until the client's timeout.

The original 15 pilot episodes are invalid infrastructure observations. They
must not be included in model comparisons or used to replace any model.

## How the cause was isolated

The diagnosis used the exact persisted first-turn Matplotlib prompt and
Nemotron-3 Nano. The rendered payload contained 1,926 text tokens, used five
`EncodedTextChunk` values, occupied 2.94% of the 65,536-token context with a
32-token allowance, and had token hash:

```text
b7165ed73a4f86474608699f9991cb981a034b2f388aa44f1d40459f088c7a6e
```

Six prompt ablations all completed in 2.1–3.1 seconds:

| Case | Input tokens | Result |
|---|---:|---|
| Short workspace-tool control | 322 | completed |
| Short bash-tool schema | 325 | completed |
| Long neutral prompt | 1,773 | completed |
| Real harness with short task | 432 | completed |
| Short harness with real task | 1,819 | completed |
| Full real prompt | 1,926 | completed |

The same full prompt then completed with output allowances of 64, 128, 256,
and 512 tokens. The 256- and 512-token requests emitted a parsed bash tool
call. This excluded prompt content, prompt length, tool schema, renderer
structure, and output allowance.

The decisive comparison changed only the sampling seed:

| Prompt | Seed | Result |
|---|---:|---|
| Full real prompt | ordinary eight-digit seed | completed in about 3 seconds |
| Same full real prompt | 20,260,726,000 | timed out after 61.7 seconds |

The large-seed reproduction used a fresh sampling client and the direct
diagnostic path, so it did not depend on mini-swe, Docker, worker threads, or a
reused failed session.

## Fix

Two safeguards are now present:

1. `TinkerMiniSweModel` uses `experiment seed + call index`; it no longer
   multiplies the seed.
2. `TinkerSamplingAdapter` maps every non-null seed into `[0, 2^31 - 1]`
   before constructing Tinker's sampling parameters.

The second safeguard protects future provider-neutral callers even if they
pass a larger Python integer.

The new treatment manifest is
`configs/model_pool_coding_v3.json`. It records
`seed_policy: signed-int32-modulo-v1` and
`harness_version: mini-swe-tinker-v2`. The v3 protocol lock also hashes the
runner and Tinker adapter source, which the earlier lock omitted.

## Post-fix verification

A real Matplotlib mini-swe episode was rerun with the original worker-thread
architecture, a 512-token per-turn allowance, a 60-second request timeout, and
a $0.04 hard episode cap.

It completed:

- 29 model calls;
- 134,582 input tokens and 4,228 output tokens;
- multiple visible bash tool calls and returned tool results;
- 66.6 seconds of wall time;
- zero provider failures;
- $0.028336350 of conservative list-price cost.

The episode eventually stopped at its deliberately small budget. It did not
pass the strict structural gate because the model once named an undeclared
`str_replace_editor` tool. That is a model/harness-format observation, not a
transport failure, and one episode is insufficient to evaluate its rate.

## Experimental consequence

The v2 early-stop result is superseded. A fresh v3 pilot must use new output
paths and must not resume or combine with the invalid v2 records. The five-model
pool remains unchanged. The fixed 500 × 5 × 3 matrix remains paused until the
fresh 12-task-per-model gate is evaluated.

## Cost accounting

The controlled diagnosis and verification added $0.070076415 of conservative
exposure. Total conservative exposure under the existing $60 authorization is
now $2.406596660, leaving $57.593403340. Timed-out calls are charged at their
full preflight reservation because actual provider usage was unavailable.
